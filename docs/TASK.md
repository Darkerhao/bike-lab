# 项目任务：BIKE LAB — 高精度交互式自行车 3D 拆解与传动仿真系统

## 一、项目定位

请使用原生 HTML、CSS、JavaScript 和 Three.js，开发一个完整的、可交互的、高品质自行车 3D 机械结构展示网页。

项目名称：**BIKE LAB — 智能自行车实验室**

这不是一个简单的自行车模型展示页面，而是一个具有工业级产品可视化质感的 3D 机械拆解与教学演示系统。

参考高端汽车工业展示网站、机械工程 CAD 爆炸图、航空航天数字孪生系统的视觉效果。

核心目标：

1. 展示一辆高精度现代公路自行车。
2. 允许用户从任意角度观察自行车及其机械结构。
3. 支持零部件独立选取、聚焦、说明和拆解。
4. 支持完整自行车的分层爆炸式拆解与自动组装。
5. 真实模拟自行车脚踏传动系统。
6. 通过科技感 UI 提供专业、直观、沉浸式的交互体验。

**最终效果要求：视觉上接近高端 3D 工业产品展示平台，而不是普通后台管理系统。**

# 二、技术架构与开发约束

## 2.1 技术栈

必须使用：

- HTML5
- CSS3
- 原生 JavaScript ES Modules
- Three.js
- Three.js OrbitControls
- Three.js 后处理模块（EffectComposer、RenderPass、UnrealBloomPass 等）

通过 CDN 引入 Three.js。

建议统一使用 Three.js r180，所有 Three.js 核心模块和 addons 必须保持同一版本。

推荐模块导入方式：

使用 importmap 配置 three 和 three/addons/ 的映射，避免不同 CDN 路径造成版本冲突。

禁止使用：

- React
- Vue
- Angular
- TypeScript
- Tailwind CSS
- 其他前端框架
- 外部 GLTF、GLB、OBJ、FBX 等现成自行车模型
- 预渲染图片模拟 3D 模型

所有自行车模型必须通过 Three.js 几何体、曲线、材质和程序化建模生成。

允许使用原生 SVG 绘制 UI 图标。

## 2.2 文件要求

所有代码必须整合到：

index.html

包括：

- HTML 页面结构
- CSS 样式
- JavaScript 业务逻辑
- Three.js 场景构建
- 自行车程序化建模
- 零件交互
- 拆解与组装动画
- 传动仿真
- UI 控制逻辑

不需要安装任何 npm 依赖，不需要构建工具。

在联网环境下，通过本地 HTTP 服务即可运行。

注意：ES Module 页面不保证支持 file:// 直接打开，应提供明确的运行说明。

# 三、整体视觉设计

## 3.1 设计风格

采用高端工业科技风格。

视觉参考：

- Apple 产品 3D 展示页面
- 高端汽车数字孪生系统
- 工业机械 CAD 爆炸图
- 科技产品发布会视觉效果
- 专业机械工程仿真软件

整体视觉关键词：

Premium、Industrial、Futuristic、Precision、Mechanical、Minimal、Cinematic。

## 3.2 色彩系统

以深色为主，采用蓝青色作为交互强调色。

建议颜色：

| 元素 | 颜色 |
|---|---|
| 页面背景 | #080B12 |
| 3D 展示区域 | #0B1019 |
| 面板背景 | rgba(16, 23, 36, 0.88) |
| 主强调色 | #00D9FF |
| 辅助强调色 | #3987FF |
| 选中高亮 | #00E5FF |
| 普通文字 | #E8EDF5 |
| 次级文字 | #8794A8 |
| 分割线 | rgba(255,255,255,0.08) |

强调色只用于交互状态、选中零件、数据指示线和少量装饰。

避免大面积霓虹光效。

## 3.3 3D 场景视觉

自行车是整个页面的绝对视觉中心。

要求：

1. 使用深色工业展示环境。
2. 地面具有柔和反射效果。
3. 使用真实的环境光、主光源、补光和轮廓光。
4. 自行车下方具有柔和接触阴影。
5. 金属零件能够呈现清晰的高光和反射。
6. 碳纤维车架体现细腻的材质质感。
7. 橡胶轮胎与金属轮圈具有明显材质差异。
8. 支持适度的环境光遮蔽和 Bloom 后处理。
9. 保证模型结构清晰，不允许过度曝光。
10. 初始状态展示自行车的 45 度前侧视角。

增加非常轻微的环境粒子或科技网格装饰，但不能影响模型观察。

可以在地面增加低透明度的圆形网格、坐标轴和尺寸参考线，增强工业设计感。

## 3.4 页面动效

页面加载时：

- UI 面板渐入。
- 3D 场景平滑出现。
- 自行车从轻微缩小状态过渡到正常展示状态。
- 默认展示完整装配的自行车。
- 加载过程提供简洁的进度提示。

所有动效应流畅自然。

避免过度动画、频繁闪烁和影响操作的视觉效果。

# 四、自行车高精度 3D 建模

## 4.1 整体模型

以现代碳纤维公路自行车为原型。

设计要求：

- 真实公路自行车比例。
- 700C 轮径。
- 双三角车架。
- 弯把公路车结构。
- 前后碟刹。
- 后轮多片飞轮。
- 后拨链器。
- 外露式链条传动系统。
- 现代公路自行车涂装。

模型应具有明显的工业设计细节。

建议以自行车局部坐标系建立模型：

- X 轴：自行车前后方向。
- Y 轴：左右方向。
- Z 轴：垂直方向。

所有零件都应具有明确的空间位置和装配关系。

建议尺寸：

- 前后轮直径：约 700mm。
- 轴距：约 1000mm。
- 车架五通高度：约 270mm。
- 座管长度：约 520mm。
- 前叉长度：约 370mm。

实际尺寸可根据视觉比例调整，但所有零件必须保持合理的相对位置。

## 4.2 车架系统

车架不能使用简单的方块拼接。

必须使用 TubeGeometry、CatmullRomCurve3 或自定义管状几何体构建真实管件。

至少包括：

- 上管
- 下管
- 立管
- 头管
- 后上叉
- 后下叉
- 五通区域
- 头管连接节点
- 后轮叉端

要求：

1. 体现现代公路车的双三角结构。
2. 管件连接位置自然。
3. 管径根据不同管件进行区分。
4. 管件表面有适度倒角或圆润过渡。
5. 体现碳纤维涂装效果。
6. 重要连接处加入金属套筒、螺栓等细节。

## 4.3 前叉与转向系统

包含：

- 前叉左右叉腿
- 前叉肩
- 头管轴承区域
- 把立
- 车把
- 车把弯曲区域
- 刹车手变
- 握把胶套

车把使用曲线几何体构建，体现公路弯把的真实形状。

## 4.4 坐垫系统

包含：

- 坐垫
- 坐垫底座
- 坐垫支撑结构
- 座管
- 座管夹
- 固定螺栓

坐垫应有符合人体工程学的轮廓，而不是简单长方体。

## 4.5 车轮系统

前后轮均需要独立建模。

每个车轮包含：

- 橡胶外胎
- 胎纹
- 轮圈
- 轮圈侧壁
- 辐条
- 辐条帽
- 花鼓
- 轴心
- 轮轴端盖

重点要求：

**轮胎：**

- 使用圆环或自定义轮胎截面建模。
- 表现橡胶的粗糙质感。
- 增加细小胎纹。
- 轮胎与轮圈之间具有清晰分界。

**轮圈：**

- 采用现代公路车深框轮圈。
- 表面具有金属或碳纤维材质。
- 展示轮圈内部结构。

**辐条：**

- 使用真实的细长金属几何体。
- 采用交叉编织布局。
- 左右侧辐条分别连接对应花鼓法兰与轮圈。
- 前后轮分别具有独立辐条组。
- 不允许所有辐条都从轮轴直接辐射到轮圈而不体现编织关系。

**花鼓：**

- 中央轴体。
- 左右法兰。
- 轴承端盖。
- 后轮增加塔基结构。

## 4.6 制动系统

前后轮都需要配置碟刹系统。

包含：

- 制动盘
- 制动盘安装座
- 碟刹盘孔洞
- 制动卡钳
- 卡钳固定螺栓
- 刹车油管
- 刹车片结构

碟刹盘必须使用金属材质。

通过圆环、薄圆柱、孔洞等几何组合体现真实的碟刹结构。

## 4.7 传动系统

这是整个模型的重点。

必须尽量还原真实自行车传动结构。

包含：

- 牙盘
- 牙盘齿片
- 曲柄
- 左右脚踏
- 链条
- 后飞轮
- 飞轮多级齿片
- 后拨链器
- 导轮
- 张紧轮
- 五通轴心
- 链条连接结构

**牙盘：**

采用圆形齿盘结构，齿片应具有可辨识的机械齿形。

**曲柄：**

采用金属曲柄结构，左右曲柄呈 180 度相位差。

**脚踏：**

具有踏板主体、轴心和防滑表面。

**链条：**

不能只使用一条普通圆管代替链条。

应使用程序化链节结构，至少能够辨识：

- 链板
- 链销
- 滚子

如果使用 InstancedMesh 优化链节数量，必须确保链条具有真实的机械视觉效果。

链条路径应准确绕过牙盘、后飞轮及后拨导轮。

**后飞轮：**

采用多级同心齿片结构，不同齿片直径不同。

**后拨链器：**

需要体现：

- 固定支架
- 导向臂
- 张紧臂
- 上导轮
- 下导轮
- 链条经过导轮的路径

# 六、核心交互系统

## 6.1 三维视角控制

使用 OrbitControls。

支持：

- 鼠标左键拖动旋转。
- 鼠标滚轮缩放。
- 鼠标右键平移。
- 双指缩放。
- 触摸旋转。
- 惯性阻尼。
- 限制不合理的翻转角度。
- 限制最近和最远缩放距离。

支持快捷视角：

- 正视图
- 侧视图
- 俯视图
- 后视图
- 默认 45 度视图

视角切换必须带有平滑动画。

## 6.2 零件选取

使用 Raycaster 实现真实三维射线拾取。

交互要求：

鼠标悬停：

- 零件出现轻微高亮。
- 显示中文名称。
- 鼠标指针变为可交互状态。

点击零件：

- 当前零件进入选中状态。
- 使用独立材质或轮廓高亮显示。
- 其他零件适当降低视觉权重，但不能完全隐藏。
- 右侧信息面板切换为对应零件信息。
- 显示零件名称标签。
- 必要时绘制连接指示线。
- 可以通过聚焦按钮将相机平滑移动到零件附近。

再次点击其他零件时，正确切换选中状态。

禁止通过修改整个场景的材质来实现单个零件高亮。

## 6.3 零件聚焦

提供：

- 聚焦当前零件。
- 显示关联零件。
- 隐藏当前零件。
- 单独恢复当前零件。
- 查看零件详情。

聚焦时，摄像机围绕当前零件平滑移动。

## 6.4 单个零件拆解

点击左侧零件清单或右侧操作按钮，可以拆解当前选中零件。

要求：

1. 零件从当前装配位置平滑移动到拆解位置。
2. 根据零件所在系统自动确定展开方向。
3. 保留其原始装配姿态。
4. 不允许旋转后产生不合理的姿态。
5. 拆解完成后可以重新组装。
6. 重复操作不能产生位置累计偏移。

拆解位置必须基于原始装配位置计算，而不是基于当前已经移动的位置计算。

## 6.5 一键全部拆解

提供专业的爆炸图模式。

将自行车分为多个机械层级：

第一层：车架及主体结构。

第二层：前叉、车把、坐垫、座管。

第三层：前后车轮。

第四层：制动系统。

第五层：传动系统。

第六层：牙盘、曲柄、脚踏、飞轮、链条及后拨。

各部件沿着合理的机械拆装方向逐渐展开。

重要要求：

- 零件之间保持合理间距。
- 避免严重重叠。
- 展开方向与真实装配方向相关。
- 不允许所有零件统一向外飞散。
- 各层级具有清晰的空间关系。
- 保持模型整体结构可辨认。

增加爆炸图连接线，用于指示零件原始安装位置。

## 6.6 拆解进度控制

底部提供 0%—100% 拆解进度滑块。

规则：

- 0%：完整装配。
- 25%：轻度拆解。
- 50%：主要系统展开。
- 75%：大部分零件展开。
- 100%：完整爆炸图。

滑块需要支持连续拖动。

所有零件的位置根据拆解进度实时计算：

currentPosition = lerp(originalPosition, explodedPosition, progress)

禁止使用累加位移。

滑块拖动过程中，模型需要实时更新，不能等拖动结束后才执行动画。

## 6.7 重新组装

点击重新组装：

- 所有零件回到原始装配位置。
- 拆解连线消失。
- 选中状态合理保留或清除。
- 动画平滑。
- 最终与初始装配状态完全一致。

# 七、真实传动系统仿真

这是本项目的重要演示功能。

提供：

- 开始传动
- 暂停传动
- 调节转速
- 调节传动档位
- 实时显示转速数据

## 7.1 传动逻辑

当用户启动传动时：

1. 左右曲柄以相反方向的空间相位安装，绕五通轴旋转。
2. 左右脚踏跟随曲柄运动。
3. 牙盘与曲柄同步旋转。
4. 链条沿牙盘、后飞轮和后拨导轮路径循环运动。
5. 后飞轮与后轮花鼓联动。
6. 后轮随传动系统旋转。
7. 前轮保持静止。

传动速度必须符合齿轮传动关系。

使用以下公式：

后轮角速度 = 曲柄角速度 × 牙盘齿数 / 后飞轮齿数

链条线速度 = 曲柄角速度 × 牙盘节圆半径

注意：

- 角速度需要使用统一的弧度单位。
- 左右曲柄相位差为 180 度。
- 链条运动速度与牙盘和飞轮的旋转速度一致。
- 后轮旋转方向符合自行车前进时的方向。
- 不允许将前轮、后轮和牙盘简单地设置成相同旋转速度。

## 7.2 链条动画

链条必须沿真实闭合路径运动。

建议：

使用 CatmullRomCurve3 或自定义路径计算链条各链节的位置和切线方向。

链条各节按照固定间距沿路径运动。

动画更新时根据时间推进链节在路径中的位置。

确保：

- 链条不脱离齿盘。
- 链条不会突然跳跃。
- 链条速度与牙盘转速匹配。
- 后拨导轮区域链条路径正确。

## 7.3 传动仪表盘

增加科技感数据展示区域：

- 当前踏频 RPM。
- 牙盘齿数。
- 后飞轮齿数。
- 当前传动比。
- 后轮转速 RPM。
- 当前模拟速度。

提供一个可调节踏频的控制器，例如 30—120 RPM。

切换后飞轮档位时，重新计算传动比。

以上数据属于程序模拟数据，明确标注为仿真值。

## 7.4 状态限制

当拆解进度大于 0 时：

- 自动暂停传动。
- 禁止启动传动。
- 显示提示：请先完成自行车组装。

拆解期间不能继续驱动已经分离的机械零件。

# 十、动画与交互品质

所有动画使用统一动画管理机制。

禁止直接在多个事件回调中随意修改零件位置。

建议使用 requestAnimationFrame 作为统一动画循环。

动画至少包括：

1. 页面初始进入动画。
2. 模型入场动画。
3. 零件悬停高亮。
4. 零件点击选中动画。
5. 零件聚焦动画。
6. 单零件拆解动画。
7. 全局爆炸拆解动画。
8. 全局组装动画。
9. 传动动画。
10. 视角切换动画。
11. 面板展开收起动画。

拆解动画建议采用 easeInOutCubic 或 smoothstep 等缓动函数。

拆解状态和传动状态需要互斥管理。

所有零件的位置、旋转和缩放必须有准确的初始状态记录。

# 十一、Three.js 性能优化

必须考虑模型的实时渲染性能。

要求：

1. 合理复用 Geometry 和 Material。
2. 重复螺栓、辐条帽等零件优先使用 InstancedMesh。
3. 减少不必要的 Mesh 数量。
4. Raycaster 只检测可交互对象。
5. 动画更新只修改需要变化的对象。
6. 根据设备性能适当调整 PixelRatio。
7. 浏览器窗口变化时更新 Renderer 和 Camera。
8. 页面退出时正确释放资源。
9. 控制阴影质量和后处理开销。
10. 禁止每一帧重复创建大量几何体和材质。

目标：

在常见桌面电脑上保持流畅的交互体验。

建议正常场景目标为 50—60 FPS，低性能设备允许适当降低画质。

# 十二、代码架构与质量要求

虽然所有代码都在一个 index.html 中，但 JavaScript 必须进行逻辑模块化组织。

建议按照以下结构划分：

1. CONFIG：场景配置。
2. BIKE_DATA：自行车零件数据。
3. BikeModel：自行车模型生成。
4. ComponentManager：零件注册、选取和状态管理。
5. ExplodeController：拆解与组装控制。
6. TransmissionController：传动仿真。
7. CameraController：相机控制。
8. InteractionController：鼠标和触摸交互。
9. UIController：界面控制。
10. AnimationManager：统一动画管理。
11. App：应用初始化和生命周期。

代码必须具有：

- 清晰的命名。
- 必要的注释。
- 统一的状态管理。
- 合理的函数拆分。
- 避免全局变量污染。
- 完整的异常处理。
- 正确的资源释放。

不要把所有逻辑塞进一个巨大函数。
